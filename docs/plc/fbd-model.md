# FBD model — as-built

Status: as-built for `compiler/fbd-model`.

## Shape

- `fbd.v1` JSON document types (serde), the working/editor surface.
  PLCopen TC6 XML is the exchange surface (`plcopen-io`, P4-02).
- `from_json` / `to_canonical_json` — canonical form via struct field
  order + `BTreeMap` params: identical models serialize to identical
  bytes (verified by test, including a field-scrambled input).
- Forward-compat: unknown keys ignored on read; `schema` must equal
  `fbd.v1` — migrations hook lives in `from_json` for v2.
- `IdAlloc` — monotonic per-POU u64 allocator; `Network::node_ids()`
  feeds `alloc.over(...)` on load so ids are never reused (provenance
  durability per §6).
- `FbdProject { schema, project, pous, tasks, data_types, global_vars }`.
  `Pou { id, name, kind, interface, networks, en_eno }`. `Network`
  carries `blocks | wires | assocs | comments | labels | jumps | returns`,
  `kind` is `fbd|ladder`; ladder networks lower positionally —
  y-bands are rungs, x-order is the series chain, contacts (NO/NC)
  AND into the flow and coils latch it (see `lower_ladder`).
- `Block` covers `fb | function | operator | variable | jump_target |
  st | device`; variable blocks carry `role/name/at`, `st` blocks carry
  `pins` + `params.CODE`, and `device` blocks carry `pins` channel
  declarations. `PortSel` = index or pin name.
  `pos` is integer grid units — canvas floats are render-layer only
  (§4.2 determinism).
- `device` blocks model fieldbus terminals (e.g. Beckhoff EK modules):
  `type_ref` is the terminal name, each `pins[]` entry is a channel —
  `var_output` = device→logic, `var_input` = logic→device,
  `var_in_out` = both, and every pin must carry a valid `AT`
  process-image binding (`%I`/`%Q`/`%M`). Lowering aliases each channel
  to a located variable shared through the address map (two pins on the
  same address see the same storage), emits one `Assign` per driven
  input channel, and reads output channels as located-var references —
  no runtime device call; the EtherCAT side owns image transport.
  Device self-wiring (AI→AO on one terminal) is exempt from the
  algebraic-cycle check since each pin is a distinct located var.
- `Assoc` models the PLCopen wireless `formalParameter`+variable
  association (named stub edges, not wires).
- Node-id uniqueness per POU is validated on load
  (`ModelError::DupNodeId`) — ids key provenance (symmap, diagnostics,
  breakpoints), a collision is silent data loss otherwise.

## Schema artifact

`schema/fbd.v1.json` at repo root, generated by
`cargo run -p fbd-model --bin fbd-schema --features schema`
(schemars 0.8, draft-07). TS types for the editor are generated from
this file.

## `plcopen-io` (fbd-model.md §5 / App E)

- `export(project, Strict|Roundtrip) -> (xml, [LossNote])`.
  Strict emits TC6-only XML (no `tether:` attrs): networks flatten
  behind `--- net <id> ---` comment markers (vendor-band localIds),
  tasks drop, probe flags drop, located vars serialize by `%address`
  (friendly names lost) — each loss reported.
  Roundtrip adds `tether:network` wrappers, `tether:wire` ids (fan-out
  merge key), `tether:probe`, `tether:name`, and `addData` tasks —
  importing our own export is lossless (test-verified on the App-D
  example: blocks, wires, params, probes, annotations, tasks).
- Wire model follows TC6: `<connection refLocalId formalParameter>`
  lives on the dst `connectionPointIn`; literals become `<expression>`
  inside the pin's `connectionPointIn`; indexed pins emit
  `formalParameter="IN<n>"` (reimports to `PortSel::Index(n)`).
- `import(xml) -> ImportReport{project, notes}`: foreign/flat FBD
  folds to one implicit network; strict-export `--- net ---` markers
  re-split into segments; empty implicit nets drop. FB-instance
  localVars matching a block's (instance, type) fold into the block —
  extras (AT/init/retain) keep the decl. Elements with no `localId`
  get allocator ids (foreign `localId`s also advance the allocator so
  auto ids can't collide). `<LD>` bodies import as `ladder` networks:
  `<contact>`/`<coil>` become variable blocks (`negated` → NC,
  `<variable>`/`<expression>` → name or `%addr`, `<position>` → row),
  `connectionPointIn` links become wires, and power-rail sources are
  dropped so rail-fed elements evaluate rail-powered. `storage`/`edge`
  attributes (SET/RST coils, transition contacts) surface notes —
  the flow model supports `none` only. Non-FBD bodies
  (`<SFC>/<ST>`) report notes, not silent drops.
- `cargo run -p plcopen-io --example xml2json -- in.xml out.fbd.json`
  converts a TC6 project to the WebUI `.fbd.json` format (notes →
  stderr); `tests/ld/e2e.sh` uses it to prove imported `<LD>` bodies
  run bit-identical to their ST references.
- Coverage: real Beremiz corpus in `tools/oracle-beremiz/corpus`
  (5 project XMLs, incl. `iec61131_lang_test`) imports at 100% node /
  98.4% edge coverage — over the §13.2 ≥95% target
  (`plcopen-io/tests/beremiz_corpus.rs`).

## `fbd-lower` (fbd-model.md §4)

`fbd-lower` translates `fbd.v1` models into `tplc-mir` modules plus
`io_bindings` and diagnostics (`LowerOutput{module, io_bindings,
diags}`). Shared plumbing lives in `tplc-mir`: `diag::{Diag,Severity}`
(both frontends emit one surface; `tplc-st` re-exports it) and
`ty::{compatible, convertible, narrows, literal_fits, unify_num}`
(single coercion matrix for sema and the lowerer's FBD001 check).

- Per POU: `interface` → `VarDecl`s (kind/type/init/`at` + io binding);
  `fb` blocks → instance `VarDecl{Type::Fb}` (name synthesized
  `__fb_<id>` when absent); variable blocks with `at` and no matching
  decl → located shadow vars (`__io_*` unnamed, named when given);
  `project.global_vars` → one `GVL`.
- Per network (declared order): deterministic topo sort — frontier key
  `(exec_order==0, exec_order, y, x, id)`. Cycles release only through
  edges into `fb` blocks (feedback reads previous-cycle state);
  anything else in a cycle is FBD004 with the node-id list.
- Emission: `fb` → `Call` stmt (EN input wraps it in `If`; ENO feeds
  an `__eno_<id>` flag), `variable` out/inout → `Assign`, operators →
  folded `Bin`/`Un` expressions at consumers except `SEL/MIN/MAX/
  LIMIT/ABS/MUX` which materialize `__op_<id>` temps via `If` stmts
  (MUX: `K`-compare chain, out-of-range → first input). `*_TO_*`
  casts → `Conv`. Probed wires → `__probe_<id>` field + store at
  production; consumers read the field.
- Validation live now: all of FBD001–FBD014. InOut pins require a
  storage `Ref` source — literal/param-bound → FBD005, expression
  (operator/function output) chains → FBD014. Generic `ANY_*` ops
  check the IEC class before folding: AND/OR/XOR/NOT want BOOL,
  arith/comparison/SEL-IN/MUX-IN want ANY_NUM, shifts and MUX.K want
  ANY_INT, SEL.G wants BOOL; EQ/NE accept same-class pairs; out-of-class
  operands → FBD009.
- `params` literals parse `T#…`, based ints (`16#FF`), typed prefixes
  (`INT#5`), reals, bools, `'strings'`; bad literals → FBD006/PARSE.
- Jumps to existing labels report UNSUPPORTED (mir has no goto);
  nonexistent labels → FBD011. `return` markers emit `Return` after
  their network's work. Ladder networks reject (schema-reserved).

Interp coverage: `Rt::fb_call` now covers every builtin in
`builtin_fb_layout` — TON/TOF/TP, R_TRIG/F_TRIG, CTU/CTD/CTUD
(full `ctud_step` semantics incl. CD/LD/QD), SR/RS — matching the
`tplc-rt` reference bodies so L1 interp and native paths agree.

Verified: the doc §8 debounce example end-to-end through `Rt`
(TON timing, negated pin, probe field, %Q store), SEL → `If`,
algebraic-cycle rejection vs legal FB feedback, fan-in/exec-order/
undeclared-name errors.

## Mixed FBD + ST (one module)

`tplcc` compiles a source set containing `project.fbd.json` **plus any
number of `.st` files** into a single module. The ST frontend receives
a masked source list (`.fbd.json` entries as empty strings), so
`Prov::St{file}` indices stay globally correct and diagnostics point at
the real file.

- **FBD → ST**: an `fb`/`function` block whose `type_ref` is not in the
  fbd project resolves through the merged POU table (extern signature).
  `VAR_IN_OUT` pins are typed from the merged decl.
- **ST → FBD**: after merge, `module.pous` contains FBD-defined POUs, so
  ST `named_ty` resolves them as nominal `Type::Fb` — an ST program can
  declare and call an FBD `FUNCTION_BLOCK` directly.
- **FBD `FUNCTION` POUs** carry `ret_ty`; the lowerer emits the implicit
  return `Local` named after the POU, matching the ST frontend, so the
  value extracts identically in both engines.
- **Inline `st` blocks** (`BlockKind::St`, `pins`, `params.CODE`) are
  expanded before lowering: each becomes `BlockKind::Fb` with generated
  name `__fbd_st_<sanitized_pou>_<block_id>` and a generated
  `FUNCTION_BLOCK` whose sections come from `block.pins`
  (`var_input`/`var_output`/`var_in_out`/`var`); `CODE` is the body.
- **Duplicate implementation** (same POU in both languages) →
  `TPLC_E_MIX_DUP_POU`; a decl stub whose interface disagrees with the
  ST impl → `TPLC_E_MIX_IFACE`. A stub with an empty interface and no
  networks merges silently.
- **Multiple programs**: `layout_module` lays every `PROGRAM` into one
  state blob. With one program the field names are unchanged (no ABI
  drift); with several they are qualified `PROG.var` and `pou_scope`
  strips the prefix for per-program codegen. `tplc_init` runs every
  program's declaration initializers; `__tplc_task_<N>` wrappers and the
  descriptor's task table come from `module.tasks` (validated: a task
  binding an uncompiled program is a build-time diagnostic).

### `VAR_IN_OUT` (both languages)

An inout slot is a `Type::Ref` (u64 blob offset, `u64::MAX` = null).
Call sites bind the *caller's storage address*; the callee auto-derefs
on read and write, so writes land in the caller's storage. Scalar and
aggregate (array/struct/FB-typed) inouts both alias — this is what lets
an inline ST block configure an `FB_AtcProfile` instance's `SEG` table
member-wise (`PROF.SEG[1].KIND := …`) through a `var_in_out` pin.

Note: the FBD lowerer orders calls by data dependency, so a block that
writes an instance runs *after* the block that calls it. Config-style
blocks must therefore be idempotent or the consumer must tolerate a
one-scan delay (see `FB_AtcProfile`'s held run request).
