# FBD model — as-built

Status of `compiler/fbd-model` against `plan/06-fbd-model.md`.

## Shape

- `fbd.v1` JSON document types (serde), the working/editor surface.
  PLCopen TC6 XML is the exchange surface (`plcopen-io`, P4-02).
- `from_json` / `to_canonical_json` — canonical form via struct field
  order + `BTreeMap` params: identical models serialize to identical
  bytes (verified by test, including a field-scrambled input).
- Forward-compat: unknown keys ignored on read; `schema` must equal
  `fbd.v1` — migrations hook lives in `from_json` for v2.
- `IdAlloc` — monotonic per-POU u64 allocator; `Network::node_ids()`
  feeds `alloc.over(...)` on load so ids are never reused (provenance
  durability per §6).
- `FbdProject { schema, project, pous, tasks, data_types, global_vars }`.
  `Pou { id, name, kind, interface, networks, en_eno }`. `Network`
  carries `blocks | wires | assocs | comments | labels | jumps | returns`,
  `kind` reserved `fbd|ladder` (ladder = iter-2 hook, §11).
- `Block` covers `fb | function | operator | variable | jump_target`;
  variable blocks carry `role/name/at`. `PortSel` = index or pin name.
  `pos` is integer grid units — canvas floats are render-layer only
  (§4.2 determinism).
- `Assoc` models the PLCopen wireless `formalParameter`+variable
  association (named stub edges, not wires).
- Node-id uniqueness per POU is validated on load
  (`ModelError::DupNodeId`) — ids key provenance (symmap, diagnostics,
  breakpoints), a collision is silent data loss otherwise.

## Schema artifact

`schema/fbd.v1.json` at repo root, generated by
`cargo run -p fbd-model --bin fbd-schema --features schema`
(schemars 0.8, draft-07). TS types for the editor are generated from
this file.

## `plcopen-io` (doc 06 §5 / App E)

- `export(project, Strict|Roundtrip) -> (xml, [LossNote])`.
  Strict emits TC6-only XML (no `tether:` attrs): networks flatten
  behind `--- net <id> ---` comment markers (vendor-band localIds),
  tasks drop, probe flags drop, located vars serialize by `%address`
  (friendly names lost) — each loss reported.
  Roundtrip adds `tether:network` wrappers, `tether:wire` ids (fan-out
  merge key), `tether:probe`, `tether:name`, and `addData` tasks —
  importing our own export is lossless (test-verified on the App-D
  example: blocks, wires, params, probes, annotations, tasks).
- Wire model follows TC6: `<connection refLocalId formalParameter>`
  lives on the dst `connectionPointIn`; literals become `<expression>`
  inside the pin's `connectionPointIn`; indexed pins emit
  `formalParameter="IN<n>"` (reimports to `PortSel::Index(n)`).
- `import(xml) -> ImportReport{project, notes}`: foreign/flat FBD
  folds to one implicit network; strict-export `--- net ---` markers
  re-split into segments; empty implicit nets drop. FB-instance
  localVars matching a block's (instance, type) fold into the block —
  extras (AT/init/retain) keep the decl. Elements with no `localId`
  get allocator ids. Non-FBD bodies (`<SFC>/<LD>/<ST>`) report notes,
  not silent drops.
- Coverage verified vs a Beremiz-shaped hand fixture (inVariable →
  TON IN/PT literal → outVariable fan-in): all construct classes
  imported correctly.

## `fbd-lower` (doc 06 §4)

`fbd-lower` translates `fbd.v1` models into `tplc-mir` modules plus
`io_bindings` and diagnostics (`LowerOutput{module, io_bindings,
diags}`). Shared plumbing lives in `tplc-mir`: `diag::{Diag,Severity}`
(both frontends emit one surface; `tplc-st` re-exports it) and
`ty::{compatible, convertible, narrows, literal_fits, unify_num}`
(single coercion matrix for sema and the lowerer's FBD001 check).

- Per POU: `interface` → `VarDecl`s (kind/type/init/`at` + io binding);
  `fb` blocks → instance `VarDecl{Type::Fb}` (name synthesized
  `__fb_<id>` when absent); variable blocks with `at` and no matching
  decl → located shadow vars (`__io_*` unnamed, named when given);
  `project.global_vars` → one `GVL`.
- Per network (declared order): deterministic topo sort — frontier key
  `(exec_order==0, exec_order, y, x, id)`. Cycles release only through
  edges into `fb` blocks (feedback reads previous-cycle state);
  anything else in a cycle is FBD004 with the node-id list.
- Emission: `fb` → `Call` stmt (EN input wraps it in `If`; ENO feeds
  an `__eno_<id>` flag), `variable` out/inout → `Assign`, operators →
  folded `Bin`/`Un` expressions at consumers except `SEL/MIN/MAX/
  LIMIT/ABS/MUX` which materialize `__op_<id>` temps via `If` stmts
  (MUX: `K`-compare chain, out-of-range → first input). `*_TO_*`
  casts → `Conv`. Probed wires → `__probe_<id>` field + store at
  production; consumers read the field.
- Validation live now: FBD001 (coercion at pin insertion), FBD002,
  FBD003, FBD004, FBD006, FBD007, FBD008, FBD010 (warn), FBD011,
  FBD012, FBD013. FBD005/009/014 reserved — InOut pins have no stored
  member in the runtime today (same gap as ST), generic `ANY_*`
  resolution is via `unify_num` so unresolved cases surface as
  FBD001.
- `params` literals parse `T#…`, based ints (`16#FF`), typed prefixes
  (`INT#5`), reals, bools, `'strings'`; bad literals → FBD006/PARSE.
- Jumps to existing labels report UNSUPPORTED (mir has no goto);
  nonexistent labels → FBD011. `return` markers emit `Return` after
  their network's work. Ladder networks reject (schema-reserved).

Interp coverage: `Rt::fb_call` now covers every builtin in
`builtin_fb_layout` — TON/TOF/TP, R_TRIG/F_TRIG, CTU/CTD/CTUD
(full `ctud_step` semantics incl. CD/LD/QD), SR/RS — matching the
`tplc-rt` reference bodies so L1 interp and native paths agree.

Verified: the doc §8 debounce example end-to-end through `Rt`
(TON timing, negated pin, probe field, %Q store), SEL → `If`,
algebraic-cycle rejection vs legal FB feedback, fan-in/exec-order/
undeclared-name errors.

  `formalParameter` associations is not yet mapped back.

  doc today, not ≥95% measured.
